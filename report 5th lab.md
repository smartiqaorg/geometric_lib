# Отчёт по лабораторной работе № 5
**Тема:** Настройка CI/CD с использованием GitHub Actions

## 1. Цели и задачи работы
**Цель:** Освоить механизм непрерывной интеграции (CI/CD) на платформе GitHub, научиться настраивать автоматический запуск тестов при каждом изменении кода (push).
**Задачи:**
- Изучить синтаксис workflow-файлов GitHub Actions.
- Создать файл конфигурации `.github/workflows/main.yml`.
- Настроить запуск unit-тестов (из предыдущей лабораторной работы) на двух операционных системах: `ubuntu-latest` и `windows-latest` с использованием матрицы сборки.

## 2. Описание проделанной работы
Для автоматизации процесса тестирования в корне репозитория была создана директория `.github/workflows/`, в которой размещен файл `main.yml`. 

Данный workflow настроен на срабатывание события `[push]` (каждый раз, когда разработчик отправляет изменения в репозиторий). Внутри файла настроена стратегия `matrix`, которая порождает две параллельные задачи (job):
1. Запуск на виртуальной машине с ОС Ubuntu (`ubuntu-latest`).
2. Запуск на виртуальной машине с ОС Windows (`windows-latest`).

В рамках каждой задачи выполняется следующий алгоритм действий (steps):
- Клонирование репозитория (`actions/checkout@v4`).
- Установка интерпретатора Python версии 3.12 (`actions/setup-python@v5`).
- Запуск unit-тестов с помощью фреймворка `unittest` командой `python -m unittest discover -v`.

## 3. Листинг workflow-файла (main.yml)

```yaml
name: Tests

on: [push]

jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: python -m unittest discover -v
```


## 4. Результаты выполнения

После отправки изменений в удаленный репозиторий (`git push`), на вкладке **Actions** платформы GitHub автоматически запустился процесс тестирования.

Обе задачи (для Ubuntu и Windows) успешно завершились (статус успеха). Это подтверждает, что написанный ранее код (библиотека фигур и unit-тесты) является кроссплатформенным и корректно работает в средах Linux и Windows.


## 5. Выводы

В ходе лабораторной работы был успешно настроен пайплайн непрерывной интеграции (CI) с помощью GitHub Actions.
